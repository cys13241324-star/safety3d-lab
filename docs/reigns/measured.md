# 실측 — shipped 코드를 그대로 돌려서 잰 것

Python 재구현이 아니라 `reigns.html` 의 `<script>` 블록을 JScript 로 eval 하고
DOM 을 흉내 내어 **실제 클릭 핸들러를 눌러** 잰 값이다.
하네스: `tools/harness.js` · 실행 `cscript //Nologo tools\harness.js reigns.html 300`

플레이어 모델
- **knows N%** — 규정을 아는 비율 N. 그 확률로 준수 선택을, 아니면 반대를 고른다. 수험생 모델.
- **balance the weakest** — 카드를 안 읽고 게이지만 본다. 안전·감독이 최저면 준수, 공정·예산이 최저면 위반.
- **coin flip** — 무작위.

목표: 규정을 아는 사람 60일 도달률 **55~70 %**, 무작위 **10 % 미만**.

## 1. 구조 결함 두 가지 (수치 조정으로는 못 고친다)

### ① 정답이 56장 전부 왼쪽에 있다

```
왼쪽(a) 선택이 규정 준수인 카드: 56 / 56
오른쪽(b) 선택이 규정 준수인 카드: 0 / 56
```

### ② 효과 부호가 55장 전부 같다

| | 안전 | 공정 | 예산 | 감독 |
|---|---|---|---|---|
| 준수(a) 평균 | **+8.3** | −5.3 | −5.4 | **+5.3** |
| 오르는 카드 | 55/55 | **0/55** | **0/55** | 55/55 |
| 위반(b) 평균 | **−13.2** | +5.3 | +2.8 | −7.9 |
| 오르는 카드 | **0/55** | 55/55 | 45/55 | 0/55 |

**준수로 공정·예산이 오르는 카드가 하나도 없다.** 합법적으로 일정과 돈을 버는 길이 없으므로
규정을 다 지키면 반드시 파산한다. 그리고 좌우가 고정이므로 **카드를 읽지 않아도 게이지만 보고
좌우를 번갈아 누르면 최적 플레이가 된다.** 학습 도구로서 치명적이다.

## 3. 처방 후보 실측 (정책당 200~300판)

`swap` = 카드마다 준수 선택이 좌우 어느 쪽에 설지 섞음
`n` = 준수 선택의 공정·예산 손실을 n 만큼 메우고 안전 이득을 2n 만큼 낮춤

| 변형 | 100% | 85% | 70% | 55% | 게이지만 | 무작위 |
|---|---|---|---|---|---|---|
| 현행 | 0 % | — | — | — | 15 % | 0 % |
| swap 만 | **0 %** | 0 % | 0 % | 0 % | 0 % | 1 % |
| swap + 자연감소 | — | — | — | — | 0 % | 0 % |
| swap + 준수비용 ×0.55 | 0 % | — | — | — | 20 % | 18 % |
| **swap + n=3** | 0 % | 36 % | **53 %** | 2 % | 0 % | 1 % |
| **swap + n=4** | **100 %** | **100 %** | **49 %** | 1 % | 0 % | 0 % |

읽는 법

- **swap 만 넣으면 지식이 많을수록 빨리 죽는다** — 100% 13.0일, 55% 29.3일. 인센티브가 완전히 뒤집혀 있다.
- **준수비용을 단순히 깎는 것(×0.55)은 최악** — 무작위 18 %, 게이지만 20 %, 아는 사람 0 %. 모르는 사람이 아는 사람을 이긴다.
- **n=3 은 비단조** — 70 % 가 53 % 로 최고인데 100 % 는 0 %. 「가끔은 어겨야 산다」를 가르치게 된다.
- **n=4 만 단조 증가**하고 무작위·게이지만 보기를 0 % 로 눌러 둔다. 다만 85 % 가 100 % 라 상급자에게 긴장이 없다.

**권고: swap + n=4 를 바닥으로 잡고, 85 % 구간이 70~80 % 로 내려오도록 미세조정한다.**
n=3.5 상당(공정·예산 손실 보전 4, 안전 이득 −6)이 그 자리에 있을 가능성이 크다.

다만 n 조정은 **모든 카드에 같은 상수를 더하는 방식**이라 임시 처방이다.
제대로 된 해법은 3절의 구조 문제를 카드 단위로 푸는 것 — 아래 4절.

## 4. 수치 말고 설계로 풀어야 하는 것

1. **준수가 이득이 되는 카드를 만든다.** 재작업이 없어져 공정이 오르는 경우, 과태료를 피해 예산이 남는 경우,
   보험료·입찰 가점처럼 실제로 돈이 되는 경우. 지금은 0장이다.
2. **위반이 손해가 되는 카드를 만든다.** 지금 위반은 45/55 카드에서 예산이 **오른다**. 과태료·작업중지·
   재시공은 위반의 즉각적 금전 손실이다.
3. **부호 패턴을 카드마다 다르게 한다.** 그래야 매 카드에서 다시 계산하게 되고, 게이지만 보는 전략이 죽는다.
4. **좌우를 섞는다.** 이것 하나로 「게이지만 보기」가 15 % → 0 % 로 떨어진다.

## 6. 재설계를 넣고 다시 잰 것 (2026-09-05)

위 1~5절은 **부호 설계·좌우 섞기를 넣기 전** 판을 잰 것이다. 그 처방을 카드 단위로
넣고(P형 20장 / B형 20장), 시트를 틀렸을 때만 띄우도록 고친 뒤 다시 쟀다.

`cscript //Nologo tools\harness.js reigns.html 600`

| 정책 | 평균일 | 중앙 | 60일 도달 | 판당 시트 | 하루당 시트 |
|---|---|---|---|---|---|
| knows 100% | 61.0 | 61 | **100 %** | 11.6 | **0.19** |
| knows 85% | 53.2 | 61 | **61 %** | 17.7 | 0.33 |
| knows 70% | 41.6 | 42 | 27 % | 19.8 | 0.48 |
| knows 55% | 24.5 | 22 | 2 % | 15.1 | 0.62 |
| 게이지만 보기 | 20.1 | 18 | **1 %** | 13.2 | 0.66 |
| 무작위 | 21.3 | 19 | **1 %** | 13.7 | 0.64 |
| 늘 왼쪽 | 20.9 | 19 | **0 %** | 13.6 | 0.65 |

**3절의 구조 결함 두 가지는 사라졌다.** 「게이지만 보기」가 15 % → 1 %, 「늘 왼쪽」이
0 %다. 카드를 읽지 않고는 이길 수 없다. 목표치(아는 사람 55~70 %)는 knows 85 %
구간이 61 % 로 정확히 들어왔다.

**남은 것은 천장이다.** knows 100 % 가 600판 전부 60일을 넘긴다(종료 사유도 전부 해임 없음).
5절이 예고한 「상급자에게 긴장이 없다」가 그대로다. 규정을 다 아는 사람도 가끔은
자원 배분에서 몰리도록 만드는 일이 남았다.

### 시트를 언제 띄우는가

고치기 전에는 **카드마다 예외 없이** 시트가 떴다. 위 표의 `판당 시트` 는 고치기 전
`평균일` 과 정확히 같았다 — 60일이면 팝업 60회, 확인 클릭 60회다.

지금은 **틀렸을 때·사고 카드·본사 보고**에서만 뜬다. 준수 선택은 게이지 변화와
결과 한 줄만 남기고 0.62초 뒤 다음 카드로 넘어간다. 그래서 하루당 시트가
1.00 에서 **아는 사람 0.19 · 모르는 사람 0.65** 로 갈렸다. 설명은 모르는 만큼만 온다.

### 시험대 이름표 결함 하나

`always comply` 정책은 「늘 왼쪽」이었다. 좌우를 섞기 전에는 그게 곧 준수였지만
섞은 뒤로는 동전 던지기와 같다. 이름표만 남아 **준수 플레이가 60일 도달 1 %** 로
보이던 것을 이번에 잡았다. 준수는 `knows 100%`(`ORA`)로 재야 한다.
기본 실행이 `knows` 4종 · 게이지만 보기 · 무작위 · 늘 왼쪽을 재도록 바꿨다.

## 7. 줄타기를 넣었다 — 관리비와 위험 확률 (2026-09-05)

6절까지의 판은 준수가 언제나 옳았다. 규정을 다 아는 사람은 600판 전부 60일을
넘겼고, 상급자에게 아무 긴장이 없었다. 실제 안전관리자의 일은 그렇지 않다.
자원이 유한해서 **어디에 쓰고 어디를 포기할지 고르는 것**이 일의 본체다.

### 무엇을 넣었나

**안전보건관리비 (재화)** — 공사비와 별개로 법에 따라 계상하는 목적 예산이다.
착공 시 3,400만원, 기성(본사 보고)마다 390만원이 들어온다. 60일을 전부 규정대로
가면 약 7,300만원이 드는데 들어오는 돈은 8,080만원뿐이라 아슬아슬하다.
카드마다 조치 비용이 다르고, **위반했을 때 안전이 크게 깎이는 규정일수록 비싸다.**

관리비가 비면 공사비를 끌어다 쓸 수 있다. 그것이 목적 외 사용 — 위법이다.
한 번이면 넘어가도 되풀이하면 적발되어 값이 커진다(감독 −8, −11, −14 …).

**위험 확률** — 미조치 위반은 사라지지 않고 위험 점수로 쌓인다. 그 점수가
오늘 하루의 확률이 되고, 매일 실제로 굴려진다.

| 미터 | 무엇 | 어디서 오나 |
|---|---|---|
| 재해 발생 | 1 − exp(−R/70) | 추락·기계·전기·붕괴 계열 미조치 |
| 중독·질식 | 1 − exp(−R/45) | 밀폐·화학 계열 미조치 |
| 중대재해 | 재해확률 × 치명비율 | 안전손실 14 이상을 어겼을수록 오른다 |

위험 점수는 그 카드의 안전손실을 그대로 쓴다. `vdt` 5 부터 `confined` 18 까지
카드마다 다른 값이라, **어느 규정이 얼마나 위험한지가 확률에 실린다.**
확률은 감추지 않는다 — 얼마를 걸고 있는지 알아야 도박이 아니라 판단이 된다.

### 잰 것 (정책당 400판)

| 정책 | 평균일 | 60일 도달 | 전용 | 주된 사인 |
|---|---|---|---|---|
| **triage 100%** | 59.0 | **64 %** | 3.5 | 공사비 108 · 중대재해 16 |
| comply always 100% | 59.6 | 58 % | 7.5 | **감독기관 168** (전용 적발) |
| **triage 85%** | 51.6 | **48 %** | 1.9 | 공사비 137 · 중대재해 60 |
| comply always 85% | 50.1 | 38 % | 3.1 | 공사비 147 · 중대재해 54 |
| triage 70% | 40.4 | 25 % | 0.5 | 중대재해 92 |
| comply always 70% | 41.1 | 27 % | 0.8 | 공사비 158 · 중대재해 90 |
| 게이지만 보기 | 18.3 | **0 %** | 0 | 근로자 안전 272 |
| 무작위 | 19.1 | **1 %** | 0 | 근로자 안전 269 |

읽는 법

- **가장 잘한 플레이가 64 %** 로 목표 밴드(55~70 %)에 들어왔다. 6절의 100 % 천장이 사라졌다.
- **분류가 무조건 준수를 이긴다** — 100 % 에서 64 대 58, 85 % 에서 48 대 38.
  「다 지켜라」가 최적이 아니게 되었고, 그게 이 판이 가르치려는 것이다.
- **FM 은 감독기관에서 죽는다.** 무조건 준수는 판당 7.5회 전용하고, 168판이 적발로 끝난다.
  돈이 유한하다는 사실을 무시한 대가다.
- **지식은 여전히 단조**다(100 > 85 > 70). 카드를 안 읽는 두 정책은 0~1 %.
- 사인이 공사비·감독기관·중대재해·근로자 안전으로 흩어졌다. 하나가 지배하지 않는다.

### 튜닝하면서 밟은 것

- **전용이 지배 전략이 될 뻔했다.** 준수를 계속하면 감독이 100 에 붙어 있어 고정
  벌칙을 통째로 흡수했다. 「전용해서라도 다 지킨다」가 최적이 되어 관리비의 뜻이
  사라졌다. 벌칙을 누진으로 바꿔서 잡았다.
- **한때 전액 준수가 100 % 죽었다.** 관리비가 마르면 남은 카드가 전부 전용이 되어
  공사비가 23 → 1 로 무너졌다(한 판 12회). 줄타기가 아니라 절벽이었다. 공급을
  6,480 → 8,080 으로 올려 풀었다.
- **비용을 눈대중으로 잡았다가 두 번 틀렸다.** 전액 준수 비용을 9,900만원으로
  추정했는데 실측은 7,300만원이었다. 그래서 harness 에 `need(M)` 칸을 넣었다.

### 아직 안 한 것

`tools/sim-balance.py` 는 게이지 네 개만 모형으로 삼아서 관리비도 확률 굴림도
모른다. 지금 판의 60일 도달률은 harness 로만 잰다. 돌리면 첫 줄에 경고가 찍힌다.

## 8. 사고는 갑자기 오지 않는다 · 카드 65장 · 인물 8인 (2026-09-05)

### 낮은 확률에 억울하게 죽는 판은 아무것도 가르치지 못한다

7절의 판은 4 % 를 굴려서 터지면 「내가 뭘 잘못했지」가 아니라 「운이 나빴네」가 됐다.
그 자리에서 학습이 끊긴다. 하인리히가 센 것은 사고 1건 뒤의 경상 29건과 무상해
300건이었다 — **사고는 갑자기 오지 않는다.** 그것을 그대로 규칙으로 만들었다.

- 어떤 위반이 **처음 터질 때는 반드시 아차사고**로 온다. 다친 사람은 없고, 대신
  「지금 세우고 고친다(관리비 지출)」와 「다친 사람은 없다」 중에 고르게 한다
- 그 경고를 무시하면 그 위험의 점수가 **1.45배**가 된다. 알고 방치한 것은 가중 사유다
- **사람이 죽는 것은 두 번째부터다.** 아차사고를 준 적 없는 위반은 사망 판정에 가지 않는다

그래서 **모든 죽음 앞에는 그 위반에 대한 경고가 한 번 있었다.** 판 끝에 아차사고와
재해 건수를 나란히 적어 하인리히의 비율을 직접 보게 한다.

### 카드 40장 → 65장

`story.md` ④⑤ 와 `story-b.md` ⑤-B·⑤-C 에 쓰여 있던 것을 붙였다. 다시 쓴 10장은
글만 가져오고 **수치는 이미 조율해 둔 게임 값을 유지**했다.

| 묶음 | 수 | 내용 |
|---|---|---|
| 다시 쓴 카드 | 10 | 같은 조문, 더 나은 상황문과 인물 |
| ⑤-A 검증된 수치 | 12 | 기존 카드가 안 쓰고 남긴 조항 |

## 9. 모바일 — 넘치는 게 아니라 겹치고 있었다 (2026-09-05)

8절에서 「430 px 에서 가로로 넘친다」고 적었는데 **틀린 관찰이었다.** 헤드리스 크롬이
창 폭을 500 px 아래로 못 내려서 500 으로 그린 뒤 이미지를 430 으로 잘라 낸 것이다.
스크린샷을 증거로 쓸 때는 **뷰포트가 정말 그 폭인지 먼저 확인해야 한다.**

진짜로 재려고 폭이 정해진 `iframe` 안에 게임을 넣었다. 미디어쿼리도 iframe 자기
뷰포트를 따르므로 이 방법은 정확하다. 카드를 26장씩 넘기며 쟀다.

| 화면 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 375×667 | 상단 바 3줄 · 게이지 가림 · 카드가 버튼 덮음 | 이상 없음 |
| 390×844 | 이상 없음 | 이상 없음 |
| 412×915 | 이상 없음 | 이상 없음 |
| 320×568 | 카드가 버튼 덮음 | 이상 없음 |

**뷰포트를 넘은 것이 아니라 서로 겹친 것**이라 `getBoundingClientRect` 로 바깥 넘침만
보던 첫 측정이 놓쳤다. 겹침은 눈으로 봐야 잡힌다.

고친 것

1. **카드 높이를 통이 정하게 했다.** `#card` 가 `position:absolute` 라 내용만큼 자라서
   아래 선택 버튼을 덮었다. `max-height:100%` · flex 세로 배치로 바꾸고 본문(`.say`)이
   그 안에서 스크롤하게 했다. 높이 튐 방지용이던 `min-height:5.2em`·`6em` 은 목적을
   다했으므로 뺐다 — 오히려 스크롤을 막고 있었다. `ux.md` ④-1 의 처방이다.
2. **상단 바 버튼의 줄바꿈을 막았다.** 「3D 실습장」이 「3D 실 습 장」으로 쪼개져 바가
   세 줄이 되고 그 뒤로 게이지가 숨었다. 좁은 화면에서는 빵부스러기도 쪽 이름만 남긴다.
3. **iOS Safari 대비.** `height:100%` 는 툴바가 없는 큰 뷰포트로 계산되어 화면 아래가
   툴바 뒤로 들어가는데 `body{overflow:hidden}` 이라 끌어올릴 수도 없었다. `100dvh`
   (미지원이면 `100%` 로 되돌아간다)와 `env(safe-area-inset-bottom)` 을 넣었다.
   헤드리스로는 재현이 안 되는 자리라 원인만 보고 고쳤다.
4. **화면이 낮을 때**(`max-height:700px`/`600px`) 계기판 안내문·단계 라벨·스와이프
   힌트를 접고, 568 px 급에서는 카드 그림까지 접는다. 읽히는 것이 먼저다.

한 번 헛다리를 짚었다. 본문이 화면에서 사라져 보여 한참 찾았는데, 실제로는
`-webkit-overflow-scrolling:touch` 가 별도 합성 레이어를 만들어 **헤드리스 캡처에만**
안 그려진 것이었다(요소 높이를 재 보니 48 px 에 글자 56자가 멀쩡히 있었다).
iOS 13 부터는 필요 없는 속성이라 지웠다. **화면이 이상하면 픽셀 말고 값을 재라.**

## 11. 무엇이 얼마나 변했는지 · 그날의 변수 · 판정 기록 (2026-09-05)

### 변화 숫자는 지금까지 한 번도 보인 적이 없었다

게이지 위에 뜨던 `+7` 같은 변화 숫자(`.dlt`)가 **`.track` 안에 들어 있었고 그 트랙에는
`overflow:hidden` 이 걸려 있었다.** 레이아웃 상자는 있고 그림만 잘려 나가는 상태라,
`getBoundingClientRect` 로 위치와 `opacity` 를 재던 첫 점검도 「보인다」고 답했다.
**화면을 확인할 때는 값과 그림을 둘 다 봐야 한다.**

트랙 밖으로 꺼내 바로 아래에 알약으로 띄웠다. 배경과 테두리를 주어 어디에 겹쳐도
읽힌다. 2.2초 동안 남으므로 준수 카드가 0.62초 만에 넘어가도 다음 카드 위에서 읽힌다.
**관리비 변화(`−140만`)도 잔액 옆에 같이 뜬다** — 이건 아예 없던 표시다.

판정 시트에는 네 게이지와 관리비 변화를 칩으로 한 줄에 늘어놓는다.

### 그날의 변수 — 12 % 로 한 수치가 두 배

현장은 계획대로만 굴러가지 않는다. 낮은 확률로 한 수치가 두 배로 움직인다.

| 게이지 | 준수 쪽 | 위반 쪽 |
|---|---|---|
| 안전 | 옆 조에서도 같은 자리를 따라 고쳤습니다 | 하필 그날 비가 내렸습니다 |
| 공정 | 앞 공정이 하루 일찍 끝나 있었습니다 | 결국 뜯고 다시 했습니다 |
| 공사비 | 옆 현장에서 자재를 빌려 왔습니다 | 그 자리에서 과태료가 나왔습니다 |
| 감독 | 최윤 감독관이 마침 그 자리에 있었습니다 | 본사 안전감사와 겹쳤습니다 |

**방향은 뒤집지 않는다.** 준수 쪽에서는 이미 오르던 것이 더 오르고, 위반 쪽에서는
이미 깎이던 것이 더 깎인다. 그래서 도박이 아니라 날씨에 가깝고, 밸런스도 대칭이라
움직이지 않는다(triage 100 % 60 % → 66 %, 무작위 1 % 그대로).

### 판정 기록

지킨 것과 넘긴 것이 그 자리에서 옆에 쌓인다. 판이 끝나야 보이는 목록은 늦다 —
**지금 몇 건을 넘겼는지 알아야 다음 카드에서 다르게 고른다.**

각 줄에는 ✓/✕ · 며칠째 · 규정 이름 · **그 카드가 물은 값** · 조문이 들어간다.
표 전체가 아니라 물은 값만 남기므로 판이 끝나면 그대로 개인 요약 노트가 된다.
1160 px 이상에서는 오른쪽에 붙박이로 서고, 좁은 화면에서는 `기록` 단추로 여는 서랍이 된다.

줄마다 **그때 무엇이 얼마나 변했는지**도 칩으로 붙는다 — 네 게이지와 관리비,
두 배가 걸린 자리에는 `×2`. 보고와 현장 카드도 게이지를 크게 흔들므로 함께 남기되
(▦ 본사 보고 · ○ 현장) 충족·미달 집계에는 넣지 않는다. 규정 카드만 세야 점수와 맞는다.

같은 조문이 ✕ 로 한 번, 며칠 뒤 ✓ 로 한 번 나란히 보이는 판이 있다 —
9절의 재출제 루프가 화면에서 그대로 드러나는 자리다.

## 12. 기습 · 사고의 결 · 새 엔딩 · 이펙트 · 온보딩 (2026-09-05)

### 사고를 백 장 쓰지 않고 백 가지로 만든다

전용 사고카드는 열 장인데 위반 태그는 백 개가 넘었다. 나머지는 전부 같은 문장으로
돌아왔다. 백 장을 새로 쓰는 대신 **위험의 결을 과목별로 나눠 문장 틀**을 짰다 —
떨어진 것(fall) · 끼인 것(catch) · 저린 것(shock) · 새어 나온 것(leak) ·
쌓인 것(strain) · 서류(paper). 아차사고 18종 · 사고 12종의 틀이 태그 이름을 받아
문장을 만든다. `catch` 는 ES3 예약어라 따옴표로 감쌌다 — 이 저장소가 `const` 로
같은 자리에서 한 번 깨진 적이 있다.

### 기습 10종

예고 없이 들어오는 것들. 옆 현장 사망사고 · 태풍 · 정전 · 불시점검 · 휴게시설 민원 ·
협력사 부도 · 규격 미달 자재 · 야간 무단작업 · 폭우 · 언론 취재. 법이 걸린 카드가
아니므로 충족·미달로 세지 않고, 대신 자원과 위험을 크게 움직인다. 하루 7.5 %.

처음에는 조치 쪽 대가를 일반 카드의 두 배로 잡았다가 **준수 플레이어가 7 % 로
떨어졌다.** 판당 다섯 번 들어오는데 매번 공정을 −10 씩 깎으면 P형 카드(공정 +5)를
밀어낼 때마다 −15 스윙이 난다. 대가를 절반으로 낮추고 **게이지별로 흩뜨렸다** —
휴게시설과 언론 취재는 오히려 공정이 붙는다.

### 과목을 고르게 뽑으니 공정이 말랐다

11절의 과목 균형이 예상 못 한 곳을 건드렸다. P형(공정 +5)은 건설·인간공학에,
B형(공정 −2)은 기계·전기·화학에 몰려 있다. 건설을 42 % 에서 18 % 로 낮추자
**공정 수입이 사라져 준수 플레이어가 공정률로 140/250 판을 죽었다.**
예전 균형은 건설 편중에 기대고 있었던 것이다. B형 59장의 공정 대가를 −2 → −1 로,
본사 보고를 −5 → −3 으로 낮춰 풀었다.

### 관리비 전용의 구멍

준수를 계속하면 감독이 100 에 붙어 있어 전용 벌칙을 무한히 흡수했다. 「전용해서라도
다 지킨다」가 다시 최적이 된다. 목적 외 사용은 실제로 시정명령을 거쳐 **사용중지**로
가므로, 여섯 번째 전용에서 판이 끝나게 했다. 새 엔딩 「목적 외 사용」이다.

### 새 엔딩 여섯

`사용중지 명령` · `예고 없이 온 것들`(기습을 두 번 이상 넘기고 감독 소진) ·
`목적이 정해진 돈`(전용 5회 이상 준공) · `경고는 다 왔었다`(아차사고 12건 이상 준공) ·
`착공기를 못 넘겼다`(14일 이내 사망) · `아무 일도 없었다`(무재해·무아차사고 준공).
엔딩은 열여덟 종이 됐다.

### 눈에 보이는 것

사고가 났는데 화면이 조용하면 숫자만 바뀐 것처럼 보인다. 사고 카드에 화면 흔들림과

국면이 바뀔 때 큰 배너를 넣었다. 전부 `prefers-reduced-motion` 에서 꺼진다.

## 13. 그림 — 감사표를 끝까지 소화한 기록

`visual.md` ① 장면 감사표는 세 묶음이었다. **재작도 21종**, **한 줄만 고치는 것 14종**,
**문제 없음 7종**. 이번에 앞의 둘을 전부 소화했다.

### 가장 큰 결함은 미관이 아니라 오답이었다

| 키 | 그린 것 | 적어 둔 것 |
|---|---|---|
| `ladder` | 58.5° | 75° 이하 |
| `horse` | 57° | 75° 이하 |
| `net` | 14.7° | 20~30° |
| `fall` | 처짐 17.5 % | 처짐 12 % |
| `grinder` | 노출각 118° | 125° 이내 |
| `trench` | (이미 고쳐져 있었다) 1 : 1.79 | 1 : 1.8 |

카드는 "75° 이하로 눕혀라"라고 하는데 그림은 58.5°를 그려 놓고 그 옆에 75°라고 적어
두었다. **이 게임의 목적이 암기라면 이건 틀린 것을 외우게 하는 그림이다.** 각도는
전부 tan 으로 다시 계산해 실각도로 그었다.

### 축척이 한 판 안에서 여러 개였다

| 키 | 섞여 있던 px/m | 고친 뒤 |
|---|---|---|
| `scaffold` | 27 (1.85 m) · 11 (5 m) | 12 |
| `stairs` | 50 · 26.7 · 32 | 24 |
| `horse` | 320 (폭) · 30 (높이) | 22 |
| `net` | 38 · 5 | 30 |
| `panelspace` | 229 (통로) · 24 (사람) | 44 |
| `plank` | 275 · 400 | 110 (평면도로 전환) |

길이가 거의 같은 두 치수선에 1.85 와 5 가 붙어 있으면 읽는 사람이 축척 감각을 잃는다.
판마다 px/m 를 하나로 고정했다. 그 결과 `rail` 은 90 cm 난간이 사람 가슴에 오고,
`robot` 은 1.8 m 울타리가 사람 키보다 높다 — **규정 수치가 몸으로 읽힌다.**

`plank` 는 축척으로 풀리지 않았다. 발판 **폭**은 입면도에서 아예 보이지 않는 양이다.
평면도로 바꾸니 폭이 화면 세로가 되어 40 cm 가 제 뜻을 갖는다.

### 선이 아무것도 잡지 않고 끝나 있었다 (14종)

`elcb` 누설전류 파선이 허공에서 끝남 · `welder` 케이블이 손에서 14 px 떨어지고 용접기에
4 px 못 미침 · `rotor` 베어링 사이에 축이 없음 · `wirerope` 매단 하중이 지면에 놓임 ·
`gangway` 선체가 수면 위 10 px 에 뜸 · `gasweld` 화기를 '5 m 이격' 치수선 한가운데
그려 두 화기가 겹침 · `pile` 셋째 버팀대가 기둥과 겹쳐 둘로만 보임.

이 부류는 한 줄이면 고쳐지는데, 고치기 전까지는 **그림이 아무 말도 하지 않는다**.

### 깊이 — 선만 그리면 다 한 평면에 뜬다

세 겹으로 나눴다. 발밑 그림자(`SH`/`SHW`, 쓰러진 자세는 넓은 타원) · 지면 결 ·
원경(`FAR`, 배경 #0E1520 에 겨우 얹은 스카이라인과 타워크레인). 원경은 바깥 작업
38장면에만 붙였다. 공장 안(`craneway`·`girdergap`)과 물속·지하는 뺐다.
덤으로 `hookring`·`overwind`·`chainblock` 처럼 비어 보이던 판이 함께 메워졌다.

### 모션 — 한 번 잘못 만들었다

치수선이 보조선 → 재는 선 → 숫자 순으로 그어지며 나타나게 했다.

처음엔 `stroke-dashoffset` 을 길이로 두고 `animation-fill-mode: forwards` 로 0 을
붙들게 했다. 180·400·700 ms 는 맞았는데 **3000 ms 에서 재는 선이 통째로 사라졌다.**
붙들린 끝 상태가 풀리면 남는 건 '안 그어진 선'이었던 것이다.

그래서 뒤집었다. 정지 상태를 `dashoffset: 0` · `opacity: 1`, 곧 **이미 완성된 그림**으로
두고 `backwards` 로 시작점만 되감는다. 애니메이션이 빠지거나 `prefers-reduced-motion`
이 켜져도 그림은 온전하다. 이건 모션 일반에 적용되는 규칙이다 —
**정지 상태가 곧 맞는 상태여야 한다.**

### 자세 · 헐거운 판

서 있는 글리프 하나로는 다쳤는지 들었는지 웅크렸는지가 안 보인다. `lift`·`bend`·
`sit`·`down`·`reach` 다섯을 만들어 9장면에 넣었다. 크게 띄워 보고 두 번 다시 그렸다

장면마다 마크업 길이를 재 중간값(291자)의 3분의 2에 못 미치는 여덟 장을 골라 다시
그렸다. 빈 곳을 장식으로 메우지 않고 카드가 실제로 묻는 것을 넣었다 — `carry` 는
무릎 굽혀 든 사람 옆에 허리로 든 사람을 나란히 놓았다.

## 14. 근로자 글리프 — 해 보고 버린 것과 채택한 것

근로자 글리프 `W()` 는 장면 전체에서 150번 넘게 쓰인다. 여기를 고치면 110장이

### 버린 것 — 형광 조끼

안전관리 게임이니 근로자에게 형광 조끼를 입히면 좋겠다고 생각했다. 세 가지로
그려 봤다(몸통에 띠 두 줄 · 조끼를 면으로 · 조끼+가는 팔다리).

**전부 실제 크기에서 뭉갰다.** 장면에서 쓰는 배율은 0.8~1.1, 곧 사람 키가
20 px 안팎이다. 그 크기에서 조끼(#C8D437)는 형체 없는 초록 덩어리가 되고,
안전모(#E3B54D)와 색이 붙어 서로를 죽인다. **20 px 에서 읽히는 색 신호는
하나뿐이고, 그건 이미 안전모가 쓰고 있다.**

크게 띄운 그림만 봤으면 좋아 보였을 것이다. 시안은 반드시 실제 크기로 같이 본다.

### 채택한 것 — 안전모 비례

대신 눈에 띈 것은 **챙이 어깨보다 넓다**는 것이었다. 챙 반폭 7.5, 어깨 반폭 5.5.
그래서 안전모가 아니라 밀짚모자로 읽히고 있었다.

| | 챙 반폭 | 돔 | 머리 |
|---|---|---|---|
| 전 | 7.5 | 5.5 | 3.1 |
| 후 | **5.8** | **4.6** | **3.0** |

챙이 머리보다 조금 넓고 어깨보다는 좁아지자 안전모가 됐다. 덤으로 사람이 가로로
3.4 px 좁아져서, `edu`·`ppe`·`contractor`·`msdprog` 처럼 사람을 여럿 늘어놓는
장면에서 안전모끼리 붙던 것이 떨어졌다. `roller` 에서 안전모가 조작부에 닿던
것도 함께 풀렸다.

## 15. 사람이 2.2 m 였다 — 글리프 높이를 잘못 알고 있었다

`W`/`P` 글리프의 전체 높이는 **31 단위**다. 안전모 돔 꼭대기가 −31, 발끝이 0.
그런데 나는 계속 **26** 으로 알고 배율을 잡아 왔다(머리 원의 중심 −18 에 반지름을
더한 값이 26쯤이라 그렇게 굳었던 것 같다). 그 결과 축척을 맞춰 그렸다고 생각한
판들이 전부 **1.19배 큰 사람**을 세우고 있었다.

판의 px/m 를 알면 사람 키는 역산된다. 재 봤다.

| 키 | 배율 | px/m | 그려진 키 |
|---|---|---|---|
| `rail` | 2.20 | 31 | **2.19 m** |
| `robot` | 1.60 | 22 | **2.23 m** |
| `horse` | 1.55 | 22 | **2.18 m** |
| `approach` | 2.80 | 40 | **2.17 m** |
| `stairs` | 1.70 | 24 | **2.15 m** |
| `ladder` | 0.90 | 13 | **2.09 m** |
| `panelspace` | 1.00 | 269 | **0.12 m** |
| `caissondig` | 0.85 | 44 | **0.60 m** |

`panelspace` 는 visual.md 가 이미 지적했던 것이다 — 70 cm 통로를 188 px 로 그려
269 px/m 인데 사람은 31 px, 곧 **10 cm 짜리 사람이 70 cm 통로에 서 있었다**.
44 px/m 로 다시 그려 통로 31 px, 사람 75 px 로 맞췄다. 이제 어깨가 양쪽에 닿는다.

`caissondig` 는 44 px/m 로는 잠함 작업실이 판에 안 들어간다. 판은 24 px/m 로
그리고 50 cm 는 상세원(×4)으로 뗐다.

`ladder` 는 다른 종류의 잘못이 같이 나왔다. 상단 돌출을 12 px 로 그려 놓고
'60 cm 이상'이라 적었는데, 사다리 자체가 28.3 px/m 이므로 0.6 m 는 17 px 다.
치수만 맞고 그림이 안 맞았던 것 — 사람 키 검사가 이걸 끌어냈다.

### 배율을 잡는 규칙

**배율 = 1.7 × px/m ÷ 31.** 26 으로 나누면 안 된다.
`tools/anchor.py` 가 이제 이걸 검사한다. 판의 px/m 이 12~60 밖이면 건너뛴다 —
상세 치수나 현장 규모 치수로는 사람 키를 잴 수 없어서, 이 제한이 오탐을
26건에서 8건으로 줄였다.

## 16. 판의 20 %가 비어 있었다 — 실제 화면에서 재 보고 알았다

장면을 격자에 늘어놓고만 보다가, 실제 게임 화면을 휴대폰 폭(360·390·430)으로
띄워 봤다. 그림이 좌우로 **레터박싱**되고 있었다.

그림 상자는 카드 폭만큼(최대 400 px) 넓은데 `viewBox` 는 `0 0 320 132` 다.
`preserveAspectRatio="xMidYMid meet"` 는 넘치지 않게 맞추므로

```
k = min(상자폭/320, 상자높이/132)
```

가 되고, 상자가 320:132(2.42)보다 가로로 길면 **높이에 맞춰지고 좌우가 남는다.**
400×132 상자에서는 80 px, 곧 판의 20 %가 빈 배경이었다.

`viewBox="-40 0 400 132"` 로 넓혔다. 그림은 그대로 가운데 0~320 에 있고,
좌우 40 씩은 배경만 채운다. 그러니 **110장을 하나도 다시 그리지 않았고**
이름표 좌표와 검사 규칙(오른쪽 318 등)도 그대로 유효하다.

대신 가장자리까지 차야 할 것들을 −40~360 으로 늘렸다.
`GND`·`FAR`(안개·스카이라인·지면 띠)·`WATER`, 그리고 판 전체를 배경으로 쓰는
장면 열하나(`ground`·`fall`·`gangway`·`confined`·`caisson`·`workplan`·
`heatwave`·`firewatch`·`elcb`·`approach2`·`gangway2`). 사고 카드의 붉은 막도.

**그림 자체가 커지지는 않는다.** 크기는 상자 높이가 정하므로 그대로다.
없어진 것은 양옆의 검은 띠다 — 그런데 그게 실제 화면에서 가장 눈에 걸리던 것이었다.

교훈: **격자에 늘어놓고 보는 것만으로는 부족하다.** 카드 안에서, 진짜 폭으로
봐야 보이는 결함이 따로 있다. `insitu.py` 로 iframe 안에 넣어 잰다
(크롬 창은 500 px 아래로 못 내려가므로 iframe 이 필요하다).

## 17. 배경 실루엣은 대부분 화면 밖에 있었다

| 넓은 데스크톱 | 4.1 | 세로 218 단위만 — **y 82~300** |

두 쪽 다 살아남는 구간은 **x 90~250 · y 85~300** 뿐인데, 일곱 장 전부 그
밖에 그려져 있었다. 가장 심한 것이 `elec` — 전주 둘이 x=60 과 x=280 이라
휴대폰에서 **둘 다 잘려 나가고 전선만 남았다.** 무엇을 그린 건지 알 수 없었다.

일곱을 그 구간 안으로 다시 그렸다. 타워크레인 · 톱니바퀴 · 전주와 애자 ·
증류탑 · 앉은 사람과 화면 · 서류판 · 경고 삼각형. 이제 휴대폰에서도
데스크톱에서도 무엇인지 읽힌다.

`slice` 를 쓰는 그림은 **잘려도 남을 구간을 먼저 정하고 그 안에 그린다.**
카드 그림(`meet`)과는 반대 규칙이다 — 저쪽은 잘리지 않고 남는 쪽이 생긴다.

## 18. 카드가 말하는 위반이 그림에 없었다

`visual.md` ③ 약속 4 — 한계 규정은 **준수 상태를 그리고** 라벨에 한계를 적는다.
위반을 보여야 하는 카드는 그 위에 **붉은 파선 유령**을 덧그려 차이를 만든다.

앞의 작업으로 준수 상태는 정확해졌다(75°·1:1.8·처짐 12 %). 그런데 카드 본문은
이렇게 말하고 있었다.

| 키 | 카드가 말하는 것 | 그림에 있던 것 |
|---|---|---|
| `trench` | "모래 지반을 **1 : 0.8** 로 깎았습니다" | 1 : 1.8 (준수)만 |
| `ladder` | "사다리를 **80°** 로 세웠고" | 75° (준수)만 |
| `fall` | "처짐도 얕습니다" | 12 % (준수)만 |

**무엇이 잘못됐는지가 그림에 없었다.** 셋에 붉은 파선 유령을 겹쳤다. 1 : 0.8 의
비탈이 얼마나 가파른지, 80° 사다리가 얼마나 서 있는지가 나란히 보인다.

`horse`(80° vs 75°)와 `rail`(85 cm vs 90 cm)은 넣지 않았다. 그 판의 축척에서
차이가 각각 **4 px 과 1.6 px** 이라 유령을 그려도 안 보인다.
**보이지 않을 것은 그리지 않는다** — 6 px 규칙과 같은 이유다.

## 19. 현상 보고 카드가 본문에 19 px 을 내주고 있었다

`visual.md` ⑥-6 이 "남는 문제 하나"로 적어 둔 것. 닷새마다 오는 현상 보고 카드는
`.say` 안에 표 세 줄과 위험 목록이 들어간다. 실제로 재 봤다.

게임 사본에 탐침을 붙여 카드를 눌러 나가며 잰다(`repcard2.py`).
**iframe 과 `--dump-dom` 은 못 쓴다** — 스크립트가 돌기 전에 DOM 을 뜬다.
화면에 보이는 `<div>` 에 결과를 써 놓고 **스크린샷을 찍어야** 시간 예산이 지켜진다.

| 화면 | 카드 / 자리 | 넘침 | `.say` 안쪽 / 보이는 |
|---|---|---|---|
| 500×640 | 164 / 169 | 0 px | **206 / 19** |
| 500×780 | 254 / 261 | 0 px | **206 / 8** |

넘치지는 않는다 — 앞서 `#card{overflow:hidden}` 과 `.say{overflow-y:auto}` 를
걸어 뒀기 때문이다. 대신 **본문 206 px 을 19 px 창으로 보게 되어 있었다.**
보고서가 사실상 안 보인다.

원인은 그림판이다. 보고 카드도 다른 카드처럼 `art` 를 104~124 px 차지하는데,
보고 카드의 그림(`SC.report`, 서류판과 막대그래프)은 장식일 뿐 아무 정보가 없다.

```css
#card.rep .art{display:none}
```

한 줄로 본문 자리가 104~124 px 늘어난다. 640 px 화면에서 19 → 약 123 px,
780 px 화면에서 8 → 약 132 px.

**보고 카드를 자동으로 붙잡는 것은 끝내 불안정했다.** 4~6일마다 오는데
누르는 시점과 카드 날아가는 애니메이션이 엇갈려 지나쳐 버린다. 위 표는 그중
붙잡힌 두 판이고, 고친 뒤의 값은 계산으로 낸 것이다. 여기서 더 매달릴 만한
일이 아니라고 판단했다 — 그림판이 없어지면 그만큼 늘어나는 것은 자명하다.

## 20. 엔딩 18종에 그림이 없었다

엔딩은 이 게임에서 가장 오래 남는 화면이다. 60일을 굴린 결과가 거기 한 장으로
정리된다. 그런데 **글자만 있었다** — 태그 · 제목 · 본문 · 교훈 · 결산 숫자 · 놓친 규정.

18종에 그림을 붙였다. 판 300×96, 지면선 86. **카드 그림과 같은 어휘**를 쓴다 —

`ending()` 은 객체를 돌려주지 열쇠를 돌려주지 않기 때문이다.

## 21. 외부 상황 — 며칠씩 가는 바깥 사정

기습(`AMBUSH`) 열 장은 **한 번 정하면 끝난다.** 그런데 바깥에서 오는 것들은 대개
며칠씩 간다. 폭염경보는 사흘을 가고 집중 감독 기간은 한 주를 간다.

**상황은 카드가 아니라 상태다.** 카드는 시작됐다는 통보이고, 거기서 고른 것이
남은 날들을 무겁게도 가볍게도 만든다(준수 쪽을 골랐으면 하루치가 절반).
며칠 남았는지 계기판에 떠 있고 매일 조용히 값을 민다.

| 상황 | 일수 | 하루 증감 | 위험 배수 |
|---|---|---|---|
| 폭염경보 | 3 | 안전 −1 · 공정 −2 | 1.12 |
| 한파 · 결빙 | 3 | 안전 −1 · 공정 −2 | 1.12 |
| 집중 감독 기간 | 5 | 공정 −1 · 감독 −1 | 1.06 |
| 자재 수급 차질 | 4 | 공정 −2 | 1.08 |
| 명절 전 주간 | 4 | 안전 −2 · 공정 +1 | 1.14 |

### 세 번 잘못 만들었다

**첫째 — 지키는 쪽을 더 때리는 세금이 됐다.** 조치 비용 배수(×1.4)와 매일 감소를
같이 걸었더니 `분류 100%` 가 55 % → 32 % 로 떨어지고 `무조건 준수 70%` 가 50 % 로
올라섰다. 지식이 단조가 아니게 됐다. 준수는 돈을 쓰는데 그 위에 배수가 얹혔기 때문이다.

**둘째 — 방향을 거꾸로 잡았다.** 압력을 위험 배수(`fo`) 쪽으로 옮겼더니 이번에는
`분류` 가 40 %, `무조건 준수` 가 47 % 로 역전됐다. `fo` 는 **미조치 씨앗을 든 쪽**을
때리는데, 씨앗을 일부러 남기는 것이 바로 분류 전략이다.
`fo` 는 씨앗을, `cost` 는 지출을 때린다 — 둘의 무게로 어느 쪽이 유리한지가 정해진다.

**셋째 — 이미 병목인 곳에 압력을 더했다.** 둘을 섞어 순서는 맞췄지만(47 대 45)
전체 도달률이 41 % 로 내려앉고 종료 사유의 절반이 `공사비 소진`(130/250)이 됐다.
**돈은 이미 이 게임의 병목이다.** 거기에 무엇을 더하면 상황이 무엇을 묻든 결국
돈 이야기가 된다.

### 고친 뒤

상황을 **시간과 위험**으로 걸었다. 비용 배수를 전부 뺐고, 상황 카드의 준수 쪽도
돈이 아니라 **하루**를 쓴다(공정 −9). 폭염이면 오후를 쉬고 결빙이면 오전이 날아간다 —
현장에서 실제로 잃는 것이 그것이다. 돈은 규정 카드의 경제로 남겼다.

| 정책 | 60일 도달 |
|---|---|
| **분류 100%** | **52 %** |
| 분류 85% | 52 % |
| 분류 70% | 44 % |
| 무조건 준수 100% | 46 % |
| 무조건 준수 85% | 50 % |
| 게이지만 보기 | **2 %** |
| 무작위 | **2 %** |

분류가 무조건 준수를 앞서고(52 대 46), 카드를 안 읽는 정책은 2 %다.
종료 사유도 흩어졌다 — 전에는 `공사비 소진` 130/250 이었는데 지금은 95 이고
`공정률 소진` 이 24 로 살아났다. **시간 압력이 실제로 걸리고 있다는 뜻이다.**

도달률은 55 % → 52 % 로 조금 내려갔다. 바깥 사정이 판을 어렵게 하는 것이
이 기능의 목적이므로 그만큼은 의도한 것이다.

### 21-1. 바깥에서 오는 것 다섯 장 더

성격에 맞는 쪽으로 나눴다 — **며칠 가는 것은 상황, 한 번으로 끝나는 것은 기습.**

| 상황 (며칠 간다) | 일수 | 하루 증감 |
|---|---|---|
| 미세먼지 경보 | 3 | 안전 −1 · 공정 −1 (위험 ×1.10) |
| 주민 민원 | 4 | 공정 −2 · 감독 −1 |

기습(한 번으로 끝) — **옆 공장 가스 누출**(바람이 이쪽이고 지하에 여덟 명) ·
**외국인 근로자 열두 명 투입**(통역 하나, 자료는 한국어뿐) ·
**본사 안전점검단**(지적 건수가 소장 평가에 들어간다).

주민 민원은 돈이 아니라 **시간대**를 뺏는다 — 야간과 이른 아침을 못 쓴다.
외국인 근로자만 돈이 든다(모국어 자료와 통역).

### 21-2. 판이 늘자 오히려 좋아졌다

| 정책 | 250판 도달 |
|---|---|
| **분류 100%** | **53 %** |
| 분류 85% | 54 % |
| 분류 70% | 38 % |
| 무조건 준수 100% | 42 % |
| 게이지만 보기 | **3 %** |
| 무작위 | **5 %** |

상황 다섯 → 일곱, 기습 열 → 열셋으로 늘자 가장 센 것 하나가 매 판 나오지 않게
되어 분산이 줄었다. 분류가 무조건 준수를 11 pp 앞선다.
종료 사유는 준공 133 · 공사비 93 · 공정률 24 로 흩어져 있다.

## 22. 카드 본문만 줄어들고 있었다

휴대폰에서 본문이 한눈에 안 들어오고 스크롤해야 읽힌다는 지적. 재 봤다.

뷰포트 609 px (요즘 휴대폰에서 주소창 있는 상태) 기준:

| 덩어리 | 높이 |
|---|---|
| 상단 바 | 49 |
| 게이지 4개 | 30 |
| 계기판(관리비 + 확률 3) | **104** |
| 일차 줄 | 18 |
| 카드 | 241 (그중 **그림 104**) |
| **본문** | **40 · 스크롤 113** |

**본문이 문장 중간에서 잘리고 있었다.**

### 원인은 기능이 많아서가 아니라 flex 설정이었다

```css
#card .art, #card .subj, #card .who, #card .topic{flex:none}
#card .say{flex:1 1 auto;min-height:0;overflow-y:auto}
```

카드는 세로 flex 이고 `max-height:100%` 다. 그림·과목·이름·조문줄이 전부
`flex:none`(= `flex-shrink:0`)이므로 **자리가 모자랄 때 줄어들 수 있는 것은
본문뿐**이다. 게다가 `min-height:0` 이라 0 까지 줄어든다.
읽어야 하는 것이 가장 먼저 사라지는 배치였다.

### 순서를 뒤집었다

```css
#card .art{flex:0 1 auto;min-height:48px}    /* 줄어드는 것은 그림 */
#card .say{flex:1 1 auto;min-height:96px}    /* 본문에는 바닥을 깐다 */
```

그림은 `viewBox` 를 `meet` 로 맞추므로 **상자가 낮아지면 작게 그려질 뿐 잘리지
않는다.** 줄일 수 있는 것을 줄이고, 못 줄이는 것에 바닥을 깔았다.

덤으로 짧은 화면(≤780)에서 확률 막대 아래 「· 낮음」 줄을 접었다 —
막대 색이 이미 같은 말을 한다. 계기판 104 → 84.

| 뷰포트 | 고치기 전 본문 | 고친 뒤 |
|---|---|---|
| 549 | 스크롤 21 | **0** |
| 609 | **스크롤 113 (문장 중간 잘림)** | **0** |
| 749 | — | 0 |

가장 긴 카드(부임 첫날, 여섯 줄)까지 549 px 에서 끝까지 읽힌다.

## 23. 휴대폰 전용 배치 — 여백을 걷어 그림에 준다

**「화면이 조잡하고 그림도 잘 안 보인다」**

§22 에서 그림을 「줄어드는 쪽」으로 만들어 본문을 살렸다. 대가가 있었다.
390 px 폰에서 그림이 48~60 px 까지 눌려 무엇을 그린 것인지 알 수 없었다.
본문과 그림이 같은 자리를 놓고 다투는 한 둘 중 하나는 진다. **다툴 자리를
늘려야 한다.**

### 세로 예산을 재 보니 71 px 이 빈칸이었다

500×749 에서 `#app` 의 자식은 여섯인데 `gap:14px` 가 넷(56 px), 거기에
`#gear{margin-top:15px}` 이 더 붙는다. 그림 한 장 값이 여백으로 나가고 있었다.

| 항목 | 전 | 후 | 근거 |
|---|---|---|---|
| `#app` gap | 14 | 9 | 덩어리마다 테두리와 배경이 이미 경계를 긋는다 |
| `#app` padding-top | 56 | 50 | 상단 바를 45 로 줄였다 |
| `#gear` margin-top | 15 | 3 | 게이지와 계기판은 한 덩어리로 읽힌다 |
| `#gear .fund .note` | 상시 | 펼쳤을 때만 | 접힘은 한 줄이 원칙이다 |
| 확률 셋(`.mrow`) | 상시 55 px | 접어서 17 px | 아래 참조 |

### 확률은 접되 최악은 남긴다

「확률을 감추지 않는다」가 이 게임의 명제다. 그래서 **지우지 않고 접었다.**
접힌 한 줄에는 셋 중 밴드가 가장 높은 것이 이름·확률·글리프·말과 함께 뜬다.

```
오늘의 위험   재해 발생 0.0 % · 낮음   ▾
```

누르면 셋 다 펼쳐지고 관리비 전망까지 돌아온다(79 → 140 px).
접힘 상태는 `localStorage` 에 남는다.

### 1판은 CSS 차례를 틀렸다

규칙을 스타일시트 앞쪽에 두었더니 뒤에 오는 **같은 굵기의** 규칙들이 이겼다.

```
line 355  #card .art{height:132px}      ← 이쪽이 이긴다
line 442  #card .art{height:104px}      ← 이쪽이 이긴다
line 103  #card .art{height:126px}      ← 한 번도 적용된 적이 없다
```

재 보니 실제 높이는 셋 중 아무것도 아닌 113 px 이었다 — flex 가 줄인 값이다.
**휴대폰 블록은 스타일시트 맨 끝에 있어야 한다.**

### 그림은 더 이상 줄어드는 쪽이 아니다

```css
#card .art{flex:none;height:116px}   /* 390 px 폰에서 좌우 여백 없이 꽉 찬다 */
#card .say{min-height:0}             /* 모자라면 본문이 스크롤한다 */
```

본문은 스크롤이라도 되지만 그림은 작아지면 그냥 안 보인다.
높이 116 은 상자 비율에서 왔다 — `viewBox` 가 400:132 이고 390 px 폰의 카드
안쪽이 342 px 이니 113 px 이면 딱 찬다. 더 키우면 위아래에 검은 띠만 생긴다.

| 뷰포트 | 그림 | 본문 스크롤 |
|---|---|---|
| 549 | (≤600 은 접는다) | 0 |
| 649 | 96 | **0** |
| 749 | **116** | **0** |

가장 긴 카드에서 그림과 본문이 **둘 다** 온전하다.

### 배경이 회색 덩어리로 보이던 까닭

`BGS` 는 340×300(비 1.13)으로 그렸는데 화면을 `slice` 로 채운다. 390×780
폰의 비는 0.5 다. 비가 두 배 넘게 어긋나니 배율이 2.6 배로 잡히고 가로로
340 중 150 만 남는다 — 형체는 사라지고 확대된 회색 면만 남는다.
사용자가 「조잡하다」고 한 것이 이것이었다.

```css
#scene svg{inset:auto -15% 0 -15%;width:130%;height:auto;aspect-ratio:340/300}
```

상자를 화면이 아니라 **그림의 비**로 잡고 바닥에 붙였다. 잘리는 곳 없이
실루엣 전체가 지평선처럼 앉는다. 위쪽은 비워 두었다 — 조용한 편이 낫다.

### ① 넘치는 몫을 돈으로 (버림)

### ② 넘치는 몫을 공정으로 (버림)

안전·감독이 88 이상이면 넘치는 몫을 공정률로 옮겼다. 균형은 살았다

### ③ 오르는 몫만 위로 갈수록 줄인다 (채택)

```js
function gainAt(v, amt){
  if(amt <= 0) return amt;              // 깎이는 몫은 손대지 않는다
  var room = (100 - v) / 16;            // 84 아래에서는 아무것도 달라지지 않는다
  return room >= 1 ? amt : Math.max(1, Math.round(amt * room));
}
```

90 을 95 로 만드는 것은 60 을 65 로 만드는 것과 같은 일이 아니다.
**내려가는 몫은 그대로** 두어야 한 번 넘긴 것이 계속 아프다.

여기에 국면마다 하방 압력을 하나씩 걸었다 — 골조기 공정, 마감기 안전, 준공기 감독.
매일 걸었더니 국면 하나가 게이지를 열여덟 칸씩 먹어 완주율이 52 → 41 % 로
내려갔다. **이틀에 한 번**으로 낮췄다. 하방 압력은 「있다」는 것이 중요하지
크기가 중요한 것이 아니었다.

고친 뒤의 모양 (200판, triage 85 %):

| 일차 | 안전 | 공정 | 공사비 | 감독 |

**넷 다 움직인다.** 준공기에 감독기관이 다시 내려가는 것이 특히 좋다 —
넘긴 것이 서류로 돌아온다는 그 장의 명제가 숫자로도 보인다.

- 랭크는 **준공하면 거의 다 S** 였다

5단인데 실제로는 1단이었다.

## 28. 계기판이 잘하는 사람에게는 켜지지 않았다

이 게임이 가장 자랑하는 장치는 「오늘의 위험 확률」이다. 확률을 감추지 않는다는
것이 명제다. 그런데 얼마나 켜져 있는지 재 본 적이 없었다. 150판씩 세어 보니

| 정책 | 계기판이 0.0 % 인 카드 |
|---|---|
| triage 100 % | **97.3 %** |
| triage 85 % | 77.5 % |
| triage 70 % | 53.4 % |

`riskNow()` 는 `st.seeds` 가 비면 세 값 전부 0 을 낸다. 잘 두면 씨앗이 비고,
본사 보고가 남은 것을 세 건씩 지운다. 결과적으로 **목표대로 두는 사람에게만
꺼지는** 계기판이었다. 확률을 보려면 일부러 져야 했다.

### 내 결정과 무관한 위험을 깐다

협력사와 기존 공장 설비의 미조치. 닷새마다 한 건, 두 건까지. 무게는 작다
(w 1.2 → 하루 1.7 %) — 계기판을 켜는 것이 목적이지 난이도를 올리는 것이
목적이 아니다. 도급인의 안전보건조치(법 제63조)가 말하는 자리이고
`contractor` 카드가 이미 그 주제를 다룬다.

### 처음에는 완주율이 5 % 가 됐다

본사 보고의 시정 예산이 협력사 씨앗까지 돈 주고 지우고 있었다. 판당 열한 건 ×
150 만원이면 1,650 만원이 그쪽으로 새고, 관리비가 말라 전용이 4.0 회까지 올랐다.

**우리 관리비로 남의 설비를 고칠 수는 없다.** 시정 예산은 내가 남긴 것에만
붙이고, 협력사 위험은 이레가 지나면 그쪽 공정과 함께 지나가게 했다.
못 고치는 대신 영원히 남지도 않는다 — 그 며칠을 확률과 함께 보내는 것이
이 장치가 만드는 유일한 부담이다.

점수와 엔딩은 「내가 남긴 것」만 센다(`mySeeds()`). 안 그러면 남의 미조치 때문에
무재해 준공이 다시 도달 불가가 된다.

| | 전 | 후 |
|---|---|---|
| 계기판이 0.0 % (triage 100 %) | 97.3 % | **8.6 %** |
| 평균 표시값 | 0.14 % | **2.22 %** |
| triage 100 % 완주 | 55 % | 47 % |
| comply always 100 % 완주 | 33 % | 27 % |

계기판이 이제 판의 아흔 퍼센트에서 켜져 있고, 균형은 20 점 차 그대로다.

## 29. 사람이 여덟인데 아무도 나를 기억하지 않았다

Reigns 의 핵심 재미는 파벌이 나를 기억하는 것이다. 이 판에는 화자가 여덟인데
(윤경아 29장 · 박성태 24 · 오만근 17 · 장영수 12 · 정민혁 11 · 한지우 11 ·
차동수 · 최윤) 누구 말을 몇 번 잘랐는지 아무도 세지 않았다. 이름표일 뿐이었다.

게이지를 하나 더 붙이지 않고 넣는다. 세는 것은 둘이고 돌아오는 것도 둘이다.

**말을 세 번 자르면 그 사람은 먼저 말하지 않는다.** 그때부터 그 사람이 가져온
위험은 아차사고를 건너뛰고 바로 사고로 온다.

> 아차사고는 공짜로 주는 경고다. 그 경고를 주는 것이 사람이다.

이 게임이 팝업 없이 가르치려는 것이 정확히 그것이다. 카드에는
「정민혁은 요즘 먼저 말하지 않습니다」 한 줄이 붙는다 — 감추면 배울 수가 없다.

**다섯 번 편을 들면 그 사람이 먼저 고쳐 놓는다.** 본사 보고에서 미조치 한 건이
공짜로 잡힌다. 판마다 사람당 한 번.

### 얼마나 보이나 (120판)

| 정책 | 누가 입을 닫은 판 | 그 표시가 붙은 카드 | 먼저 고쳐 준 것 |
|---|---|---|---|
| triage 100 % | 0 % | 0 | 판당 1건 |
| triage 85 % | 23 % | 74 | 판당 1~2건 |
| triage 70 % | 53 % | 286 | 판당 1~2건 |

잘 두는 사람은 좋은 쪽만 본다. 말을 자르기 시작하면 그때부터 보인다.
그게 맞는 배치다.

안 읽는 쪽은 0~3 %.

## 30. 눈으로는 안 보이는 어긋남 — 카드의 생성 규칙

안전관리론 세 장(산업재해조사표 · 안전보건관리규정 · 관리감독자)을 새로 썼더니
**완주율이 50 → 36 %** 로 내려갔다. 값을 다시 보니

```
새 카드   준수 [6, -3, -3, 8]      공정도 깎고 공사비도 깎는다
기존      준수 [4,  5, -2, 3]      공정을 주고 공사비를 내준다   (P형)
기존      준수 [3, -1,  5, 3]      공정을 내주고 공사비를 준다   (B형)
```

덱은 두 모양으로만 만들어져 있었다(`systems.md` ③). **준수는 공정과 공사비 중
하나를 내주고 하나를 얻는다.** 둘 다 내주는 카드는 그 카드만 유난히 무겁고,
판당 여덟 번쯤 뽑히면 100점 가까운 차이가 난다.

만들면서 두 번 스스로 틀렸다. 처음엔 `[data-theme="dark"]` 를 찾게 했는데 이
사이트는 **어두운 판이 기본이고 밝은 판을 덮어쓰는** 구조라 찾을 것은 light 였다.
그다음엔 `safety_theme` 을 CSS 안에서 찾았는데 그것은 `<head>` 부트 스크립트에 있다.
검사기가 통과했다고 말할 때는 **무엇을 안 보고 있는지**부터 의심하는 편이 낫다.

괄호 세는 자리도 한 번 걸렸다. `esc()` 의 정규식 리터럴 `/[<>&"]/g` 안의 따옴표를
문자열 시작으로 오해해 그 뒤가 전부 어긋났다. 정상으로 굴러가는 직전 커밋본을
넣어 봐도 같은 경고가 나오길래 알았다 — **대조군을 넣어 보는 것이 빨랐다.**

마지막으로 회차 링크 하나를 없는 것으로 바꿔 넣어 검사기가 잡는지 확인했다. 잡았다.

## 37. 마지막 한 칸 — 밝은 판 (2026-09-07)

D11 이 열넷 가운데 마지막이었다. 형제 다섯은 `safety_theme` 을 읽어 밝은 판으로
바뀌는데 이 페이지만 `color-scheme:dark` 고정이었다.

### 왜 한 줄로 안 끝나는지 먼저 셌다

CSS 변수만 바꾸면 될 줄 알았는데, 색을 세어 보니 **날 색이 334곳**이었다.
그중 **300곳이 `DOC()` 안** — 현장 그림 SVG 를 그리는 함수다. `#243044` 가 118회,
`#1E293C` 가 88회. 밝은 쪽으로 칠하려면 그림을 통째로 다시 그려야 한다.

### 그래서 카드를 어두운 채로 남겼다

**밝은 종이 위의 어두운 화면은 사진과 같다.** 그렇게 두는 편이 읽기도 낫고,
그림을 다시 그리지 않아도 된다. `#card` 와 `#over` 안에서만 글자·선 색을 어두운
판 값으로 되돌린다 — CSS 변수는 물려받으므로 그 두 선택자에 다시 정의하면 그
아래가 통째로 어두운 판을 쓴다.

밝은 판 색은 세 바탕 위에서 전부 AA(4.5)를 넘긴다.

| | bg #F1F4F9 | panel #FFF | panel2 #E8EDF4 |
|---|---|---|---|
| text #14202E | 14.93 | 16.46 | 13.99 |
| muted #4A5568 | 6.83 | 7.53 | 6.40 |
| dim #5C6B82 | 4.91 | 5.41 | 4.60 |
| warn #8A6210 | 4.97 | 5.48 | 4.65 |

팔레트를 안 거치고 색을 박아 둔 자리 넷도 따로 줬다 — 게이지 트랙(`#39465F`),
선택지 테두리(`#4E6086`)와 호버(`#1E2A3F`), 그리고 시트 단추. 시트 단추는 밝은
판의 `--warn`(#8A6210) 위에 글자가 `#1A1200` 이라 **3.39:1** 로 안 읽혀서 흰 글씨로
바꿨다(5.48).

### 스크립트를 하나 더 넣자 하네스가 죽었다

`FAIL init`. 원인은 하네스의 정규식이었다.

```js
SRC.match(/<script>\r?\n([\s\S]*)\r?\n<\/script>/)
```

`[\s\S]*` 가 **탐욕적**이라 첫 `<script>` 부터 **마지막** `</script>` 까지 통째로
집어삼킨다. 여태 스크립트 블록이 하나뿐이라 드러나지 않다가, 테마 단추 스크립트를
끝에 붙이자 그 사이의 닫는 태그와 HTML 주석까지 `eval` 에 들어갔다.

`*?` 로 고쳤다. 테마 스크립트를 본편과 떨어뜨려 둔 까닭은 판이 깨져도 단추는
살아 있어야 하기 때문인데, 그 결정이 여덟 달 묵은 정규식 결함을 드러낸 셈이다.

이로써 `ux.md` ① 진단표의 D1~D14 가 모두 닫혔다.

## 38. 사고 카드가 열 장뿐이라 대부분은 일반 사고로 돌아왔다 (2026-09-07)

건설을 스물 몇 장 빼면 맞출 수 있다. 그러나 그러지 않기로 한다.

**이 판은 건설현장에 부임한 안전관리자의 하루다.** 낙하물 방지망·안전난간·굴착면

## 41. 「텍스트가 너무 많다」 — 그림을 넣는다 (2026-09-07)

빈출 지도가 1,966줄 전부 글자였다. 숫자로 「상위 200개가 37 %」라고 적어 두어도
그것이 **얼마나 가파른지**는 안 보인다. 셋을 넣었다.

### 누적 곡선

주제를 빈도 순으로 쌓았을 때의 누적 기출 비중. 이 페이지의 論旨 그 자체다.

x 를 로그로 펴면 앞쪽이 편해 보이지만 **펴면 안 된다** — 앞이 가파르다는 것이
이 그림이 하는 말이라, 로그는 그 말을 지운다. 선형으로 둔다.

한 계열뿐이라 범례가 없다(캡션이 무엇을 그렸는지 말한다). 값표는 200·326 두
자리에만 단다 — 점마다 숫자를 붙이면 아무도 안 읽는다. 그 둘이 곡선 위 가까이
앉아 세로로 4 px 까지 붙길래 하나는 점 아래, 하나는 위로 갈라 25 px 를 벌렸다.
지금 덮은 만큼은 가로줄로 얹고, 짚으면 「상위 N개가 X %」를 읽어 준다.

### 행마다 빈도 막대

숫자만 늘어놓으면 눈이 못 훑는다. 길이 하나로 위아래 차이를 본다.

### 연도 칸 — 2021~2026

**이게 가장 값어치 있다.** 여섯 칸의 높이가 그해 출제 수고, 2025·2026 은 진하게
칠한다. 「산업안전보건관리비」가 `[0,0,0,0,3,4]` 로 보이면 **2025년부터 나오기
시작한 주제**라는 뜻이다. 빈도 24 가 전부 2021~2022 인 주제와는 값이 다르다.

색은 사이트가 이미 쓰는 강조색 하나로 끝냈다. 과목 여섯을 색으로 가르고 싶었지만
그러면 검증되지 않은 여섯 색 팔레트를 새로 들이게 된다 — 그럴 만한 이야기가 아니다.

### 검사기가 못 보는 자리를 만들 뻔했다

연도 칸의 클래스를 `var cls = v ? ' hot' : ' on'` 로 골라 이어 붙였더니, 파일에
`class="on"` 이 **한 번도 안 적혔다.** 검사기가 「규칙만 있고 안 쓴다」고 잡았다.

검사기를 영리하게 만들어 보려다 두 번 헛디뎠다. 조립 자리 밖까지 훑게 했더니
`'BLEVE'` 같은 데이터 값이 클래스로 둔갑해 27개가 잡혔고, 자리를 좁혔더니 이번엔
`'px'` 를 주웠다. 게다가 그 편집이 검사기 두 파일의 뒷부분을 잘라내 조용히
아무것도 안 하는 상태로 만들었다(출력도 없고 종료코드도 0이었다 — 깃에서 되돌렸다).

결국 **코드가 클래스를 그대로 적게** 고쳤다. 검사기도 사람도 찾을 수 있고, 읽기도
낫다. 검사기가 못 보는 코드를 쓰고 검사기를 고치는 것보다, 보이게 쓰는 편이 싸다.

## 42. 그림이라야 잡히는 것 · 같은 말을 세 번 하고 있었다 (2026-09-07)

빈출 지도에 대한 두 가지 지적이 왔다. 둘 다 맞았다.

### ① 「여섯 가지가 있잖아, 각각 그림이 필요하다」

「기계설비의 위험점」(fq30, 1위)은 여섯이 **「무엇과 무엇 사이인가」**로 갈린다.
그런데 그 「사이」는 글로 읽어서는 안 그려진다. 표를 아무리 잘 짜도 협착점과
끼임점의 차이가 안 보인다.

여섯을 그렸다. 같은 `120×92` 판에, 기계 부품은 무대 색으로, **위험점만 빨강으로.**
한 그림에 빨강은 한 군데뿐이다.

| 그림 | 무엇을 보여 주나 |
|---|---|
| 협착점 | 슬라이드가 내려와 고정 베드와 만나는 틈 |
| 끼임점 | 도는 숫돌과 고정된 작업대 사이 |
| 절단점 | 날 하나 — **짝이 없다**는 것이 그림으로 보인다 |
| 물림점 | 두 롤러가 서로 반대로 돌며 맞물리는 자리 |
| 접선물림점 | 풀리에 벨트가 접선으로 들어가는 자리 |
| 회전말림점 | 도는 축이 소매를 감아 들이는 것 |

셋을 더 그렸다 — 지게차의 안정도(fq24 · 수직÷수평이 빗변 하나로 보인다) ·
가설통로의 구조(fq18 · 30°/15° 와 15→10, 8→7) · 강관비계의 구조(fq18 · 1.85·1.5·2.0).
수치는 전부 해설 원문에서 옮겼다.

색은 전부 CSS 변수라 밝은 판에서도 따라 바뀐다.

### ② 「같은 말을 똑같이 계속 반복한다」

한 해설 안에서 위험점 여섯 가지가 **세 번** 나오고 있었다.

    ① 산문   위험점 여섯 가지. 협착점(왕복+고정) · 끼임점(회전+고정) · …
    ② 축약   협착(왕복+고정) · 끼임(회전+고정) · …
    ③ 표     위험점 | 무엇과 무엇 사이 | 보기

회차 원문이 「해설 → 암기 → 관련이론 → 표」를 이어 붙여 오는데, **관련이론 산문이
바로 뒤 표를 글로 옮긴 것**이다. 한 문항에서는 안 보이던 겹침이, 한 주제로 모아
놓으니 드러났다.

지우지는 않았다. **표의 첫 칸 이름이 그 문단에 80 % 이상 들어 있으면** 되풀이로
보고 「글로 된 요약 — 아래 표와 같은 내용」으로 접는다. 1,966 주제 가운데 **46개**가
접혔다. 규칙이 좁아 46개뿐이지만, 넓히면 딴 이야기를 하는 문단까지 접는다.

### 그리는 자리에서는 화면을 못 본다

`figcheck.py` 를 만들었다. 좌표가 viewBox 밖으로 나갔는지(속성값과 path 의 M·L
둘 다), id 가 겹치는지, 태그가 짝을 이루는지를 센다.

**id 겹침을 두 번 잡혔다.** 화살표 촉 `<marker id="fa">` 를 여섯 그림이 그대로
복사해 쓰고 있었고, 치수선 촉 `dS`·`dE` 도 두 그림에서 겹쳤다. `url(#id)` 는 문서
전체에서 찾으므로 같은 id 가 여럿이면 첫 번째 것만 붙는다 — 이번엔 모양이 같아
눈에 안 띄었을 것이고, 그래서 더 나쁘다.

## 43. 「접선물림점이다.」 — 주어를 잃은 문장들 (2026-09-07)

「정돈이 안 된 것 같다」는 지적이 왔다. 해설 맨 앞이 이랬다.

    · 절단점은 회전하는 운동부 자체 또는 … 밀링 커터, 둥근톱 날이 그 예다.
    · 접선물림점이다. 회전체와 거기에 걸린 벨트·체인이 만나는 …
    · 끼임점(Shear point)이다. 도는 것과 고정된 것 사이에서 생긴다.

**「접선물림점이다.」 는 주어가 없다.** 무엇이 접선물림점인지가 문장에 없다.

### 왜 그런가

회차 카드의 `back` 맨 앞 `<ul>` 은 **그 주제를 쓰는 여러 문항의 답 설명**을 이어
붙인 것이다. 한 문항 안에서는 「보기와 같은 기계요소가 단독으로 발생시키는
위험점은?」 아래 놓여 멀쩡한데, 주제 하나로 모으면 문제가 떨어져 나가 답만 남는다.

한 문항짜리 화면에서는 안 보이고, **주제로 모아야 드러나는 결함**이다.

### 잃어버린 문제를 되돌려 준다

그 조각은 어느 문항 `sol` 의 앞부분이다 — 세어 보니 1,150 개 중 **1,143 개(99.4 %)**
가 그렇다. 그러니 짝을 도로 찾아 줄 수 있다.

    문항이 짚은 곳 — 3
    [2024 1회 #12 ↗] OJT(On Job Training)의 특징에 대한 설명으로 옳은 것은?
      직장의 실정에 맞는 구체적이고 실제적인 지도가 OJT의 장점이다. 나머지 셋은 …
    [2024 2회 #1 ↗]  Off JT(Off the Job Training)의 특징으로 옳은 것은?
      훈련에만 전념할 수 있는 것이 Off JT의 장점이다. …

468 주제가 이렇게 바뀌었다. 붙지 않는 일곱은 수식뿐인 조각이라 그대로 두었다.

### 처음엔 가설이 틀렸다

`<li>` 가 `sol` 과 **같은지**로 재 보고 12.7 % 만 맞아서 가설을 접을 뻔했다.
한 건을 열어 보니 `sol` 뒤에 관련이론이 덧붙어 있어서, `<li>` 는 그 **앞부분**
이었다. 접두로 다시 재니 99.4 % 였다.

수치가 안 나올 때 가설부터 버리지 말 것. **한 건을 열어 보는 것이 빨랐다.**

## 44. 가독성은 색이 모자란 게 아니었다 — 위계가 없었다 (2026-09-07)

「별색이나 그런 게 필요하지 않을까」는 지적을 받고 색부터 보태려다 멈췄다.
세어 보니 문제는 색이 아니었다.

    보이는 것이 다 같은 무게였다.

해설이 오는 순서가 회차 원문의 순서(해설 → 암기 → 이론 → 표)였는데, 그것은
**쓰인 순서**이지 **읽는 순서**가 아니다. 수험생이 하는 일은 이렇다 — 무엇으로
갈리는지 잡고 → 외울 것을 외우고 → 진짜 문제로 확인한다.

### 세어 보고 순서를 뒤집었다

| 조각 | 주제 수 | 있던 자리 → 간 자리 |
|---|---:|---|
| 암기 | 1,956 (99 %) | 가운데 → **맨 위** |
| 표 | 1,603 (82 %) | 맨 밑 → 둘째 |
| 산문 | 577 (29 %) | 위 → 아래로, 물린다 |
| 문항 | 468 (24 %) | 맨 위 → **접어 둔다** |

**암기가 99 % 주제에 있는데 파묻혀 있었다.** 가장 값어치 있는 한 줄이다.
이제 그것만 굵고 크다 — 판에서 굵게 쓰는 자리는 하나다.

### 원문에 이미 뜻이 나뉘어 있었다

`<strong>` 11,870 곳은 **용어**, `<u>` 16,492 곳은 **외울 값**이다.

    <strong>절단점</strong>은 <strong>회전하는 운동부 자체</strong>…
    <u>절단점만 짝이 없다</u>. · <u>왕복운동 + 고정부</u>

뜻이 갈려 있는데 둘 다 밋밋하게 두고 있었다. `<u>` 에 표시를 붙였다 — 밑줄 한
줄은 글 무더기 안에서 안 보인다. 표 안의 값에도 같은 표시가 붙는다.

**색은 하나도 안 늘렸다.** 이미 있는 강조색으로 위계를 세운 것이 전부다.

### 접은 것

「글이 너무 많다」의 절반은 **문항 묶음**이었다. 확인용이지 첫 줄이 아니므로
「실제 문항 3개에서 짚은 곳」으로 접었다 — 몇 개인지는 접힌 채로도 보인다.

행의 부제에서 「N문항 출제」도 뺐다. 연도 칸이 이미 같은 말을 한다.
